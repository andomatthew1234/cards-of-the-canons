## Batch A — authoritative accounts and audit controls

- S1: Shared backend current-user authorization checking Auth disabled/existence, revocation (raw bearer token with verifyIdToken(token, true)), accountControls tombstones, current roles. Apply to all authenticated endpoints including checkout via exported guard. Firestore and Storage must deny blocked administrators immediately through server-owned authorization/control records. Account-controls missing optional fields must fail safely without locking valid enabled users. Revoke tokens when blocked/demoted. Durable tombstone-first resumable deletion, avoid deleting tombstones. Preserve required orders.
- S12: Remove permanent email bootstrap from UI/rules/storage. Safe provisioning migration: only existing current server admin claims/roles, or explicitly configured bounded server bootstrap; never silently promote mailboxes. Owner/last-owner protection enforced server-side and in rules. Current claims alone cannot bypass removal; document UID role migration. Recent MFA authentication for destructive admin actions where supported, fail closed for sensitive actions.
- S10: Rate-limited server profile mutation, deny direct mutable profile writes; avoid trigger amplification/coalesce noise. Adapt UI. S11 label client-reported activity unverified, don't present as authoritative. Ensure trusted evidence is append-only and purchase activity cannot break reconciliation.
- Retention: repository collection-group indexes + bounded paginated cleanup/TTL for activity and abuse counters. Profile/email synchronization must remain usable. Paginate Auth listing. Enforce supported security policy action requirements or remove unsupported capabilities.
- Regression tests covering disabled/revoked/deleted/demoted users, owner protection, absent fields, deletion idempotency, bounded activity.

## Batch B — commerce invariants

- S2: Persist deterministic Stripe creation parameters and creation lease. Concurrent retries must not create/release inconsistently. Cancellation during creating requests cancellation rather than releases immediately. Stripe errors/DB failures are uncertain: reconcile session before releasing, never blindly release payable stock. Strictly recheck state before returning URL. Scheduled expiry must reconcile Stripe status before stock release, handle delayed payment processing.
- S3: Query actionable reserved states before limit, repository index, paginate bounded backlog. Terminal orders cannot starve cleanup.
- S4: Separate payment/fulfilment/refund states, monotonic transitions, preserve fulfilled/cancelled. Event-ID dedupe plus business idempotency. Purchase activity creation must not abort existing-event replay. Immutable payment/order binding: session id, client reference, UID, amount, currency, live/test account context. Quarantine mismatches, handle webhook-before-session persistence safely.
- S5: Sandbox cannot consume operational stock. Restrict test checkout to server-approved testers and independent inventory or no operational mutation. Active reservation per-user/global quotas. Don't merely relabel shared stock.
- S9: Invocation-level limits and coalescing for creation retry/cancel/reconcile; terminal result caching. Refund/dispute event handling, explicit cancellation/refund semantics without unconditional shipped-stock restoration.
- Live readiness must not claim validated webhook solely by whsec_ prefix. Server-admin recorded validated launch prerequisites with operator instructions/end-to-end evidence; fail closed until configured.
- Stock ledger/release must not increment deleted/recreated or untracked product stock incorrectly; use identity/version/reservation bookkeeping. Meaningful concurrent, reordered event, >100 cleanup, Stripe uncertain outcome and test-stock tests.

### Changed areas
- Analytics (S15): `functions/src/analyticsPipeline.ts` adds `allowedRouteTemplates`, route-template matching, item-shape checks, `invalidAnalyticsEvent()`, and `prepareAnalyticsEvent()` — which normalizes the path, rejects non-template or PII-like paths, requires a real Firestore product document for `view_product`/`add_to_cart`, and rejects unknown event names before zod parsing. `recordAnalyticsEvent` in `functions/src/index.ts` now runs through that guard with a `productExists` dependency. `functions/src/validation.ts` exports `analyticsEventNames` as the single shared enum for client and server. Fixed `defineNumber` → `defineInt` (firebase-functions v7 has no `defineNumber`). New `functions/src/analyticsPipeline.test.ts`.
- Security headers (S14): `firebase.json` serving headers now add `X-Frame-Options: DENY`, an enforced `Content-Security-Policy: frame-ancestors 'none'; object-src 'none'; base-uri 'self'; form-action 'self'`, and the full policy as `Content-Security-Policy-Report-Only` (no `unsafe-eval`, no inline `script-src`). The hosting `ignore` list now drops `.env*`, `*.local`, logs, source maps and dotfiles. New `tests/security-headers.test.ts`.
- MFA password change + UID-scoped state: `src/lib/security.ts` gained `securityStateKey`/`readSecurityState`/`writeSecurityState`/`clearSecurityState`/`clearSecurityStateExcept` (all keys are `cards.security.<uid>.<name>`); `ChangeEmailFlow` no longer touches raw sessionStorage keys. `src/context/AuthContext.tsx` adds an `onIdTokenChanged` listener (re-checks account blocklist on refresh, refreshes admin claims, handles expired/invalid token errors), clears other accounts' security state and any staged action on identity change, exposes `performReauthentication`/`runPendingSecurityAction`/`cancelPendingSecurityAction`, and stages a pending `password-change` so `changePassword` returns `'mfa-required'` and completes only after the existing challenge resolves. `SecurityCentre` renders the existing `ReauthenticationPanel` for that challenge and abandons the staged action when the dialog closes.
- Image private staging and validation: `storage.rules` now defines `image-staging/{uid}/{fileName}` as owner-only (read *and* write), and makes `product-images/**` and `page-images/**` **server-write-only** — publication is a server boundary, public reads stay open. New `functions/src/images.ts` exports the `publishStagedImage` callable: admin-only via `authorizeRequest`, strict staging/destination path regexes with the captured staging UID required to equal the caller UID, ≤5 MB size check before download, `validateImageBytes()` (JPEG/PNG/WebP magic bytes against the stored content type), copy to the approved destination, then delete the staging object. Honest limitation: this is a size + declared-type + signature check; it does **not** decode or render pixels, and the docs say so. `src/lib/data.ts` `uploadProductImage` now uploads to the caller's staging path and publishes through the callable before returning the download URL.
- Deployment artifacts: new `scripts/check-dist.mjs` validates `dist/` and `functions/lib/` — file-type allowlist, no dotfiles/environment/log/map files in the hosting bundle, secret patterns (Stripe live/test keys, `whsec_` with a real payload, AWS/GitHub/Slack keys, private keys — placeholder strings ignored), no emulator endpoints, no executable inline script or scriptable URL schemes in HTML, no unresolved `${` markers, `private.html`/`404.html` noindex, referenced entry scripts present on disk, and no compiled test files or environment files in `functions/lib`. Wired into `npm run build` and exposed as `npm run artifact:check`. `functions/clean-lib.mjs` now wipes `functions/lib` before every `tsc` so stale compiled tests cannot ship; `functions/package.json` build runs it first.
- Environment ignore variants: root `.gitignore` now covers `.env.*` (with an `!.env.example` exception), `*.log` and keeps `*.local`.
- Dependency audit: `npm audit fix` applied in both trees — **functions: 0 vulnerabilities** (was 1). Root went 14 → 11; all 11 remaining are inside the `firebase-tools` CLI chain (`@opentelemetry/core`, `basic-ftp`, `braces`, `uuid` plus their `pubsub`/`proxy-agent`/`chokidar`/`gaxios` dependents: 4 moderate, 7 high). npm only offers `npm audit fix --force`, which reports it would install `firebase-tools@14.23.0` — a breaking change and a downgrade from the installed 15.33.0 — so it was **not** applied. This is a local development CLI only; it is not shipped in `dist/` or `functions/lib/` (artifact checks confirm).
